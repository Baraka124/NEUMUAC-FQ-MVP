# Phase 14H168 — Research source acquisition and extraction readiness

This phase introduces a **real-data, persistent worklist** for the complete linked bibliography already held by the CFTR research project. It does not create sources, extract trial outcomes automatically, alter original classifications, adjudicate conflicts, or grant approval to any research observation.

## Connected inventory
At the implementation audit, there were 154 references across 39 variants. They remain read from the live `public.evidence_links` table. The worklist never hardcodes totals or uses temporary production rows. Records with catalogue titles such as `PubMed article 12345678`, missing PMID fields when the link clearly contains an identifier, mismatching identifiers, or a DOI URL without a recorded DOI are flagged **for metadata checking**. These are deterministic catalogue checks, not proof of publication identity, quality or therapy response.

## Source triage
An active research contributor, reviewer or administrator can open the worklist from **Evidence & provenance** and record one of five researcher workflow states: metadata needs checking, original source located, extraction in progress, ready for source claim, or not extractable. No record starts in an assumed completed state. Each change requires a 20–700-character rationale. The database checks the submitted reference ID and expected version, locks the record, and appends a permanent event. A stale concurrent modification fails instead of silently overwriting another researcher's decision.

The panel includes:
- Real reference and variant identifiers, original citation links, publication metadata diagnostics, review claim counts and approved numeric-endpoint counts.
- Search, state/diagnostic filters, pagination, variant dossier shortcut, original source shortcut and CSV of filtered records.
- The note and actual triage revision history count. Only the current workflow state and note are displayed; sensitive account identities are not exposed.
- Source totals, variant coverage, untriaged records, metadata flags and approved/pending claim metrics, always derived from live records.
- All records are retrieved only when an authorized member explicitly opens the panel; no incomplete list is treated as a full worklist.

## Security & scientific isolation
The new `nfq_evidence_review.source_triage` and `source_triage_events` tables reside in the unexposed private schema with RLS enabled and direct anonymous/authenticated grants revoked. The public RPC `nfq_source_acquisition_worklist` checks live `auth.sessions`, `auth.uid()` and a current nonrevoked research membership. It exposes only bounded bibliographic metadata, workflow state and aggregate approved/pending counts. The caller cannot pass user IDs or reviewer roles. No mutation writes to `variants`, `evidence_links` or the two-reviewer claims/reviews tables.

This workflow **does not download paywalled full texts, assert that abstract metadata validates an endpoint, or create synthetic experimental measurements**. Source extraction still requires people to inspect original work and two independent approvals under Phase 14H166/167 before it can enter the scientific engines.

## Validation
- Supabase migration: `docs/sql/14H168_source_acquisition_worklist.sql`.
- Typed RPC contract, source URL allowlist, fail-closed inventory validation, CSV formula-injection escaping, status/version consistency, metadata diagnostic unit tests.
- Connected desktop/phone browser tests for lazy loading, recorded triage and unauthorized account isolation.
- Original five-modulator, variant reconstruction, visual regression, legacy-integrity and application build checks must pass before merge.
- Production database starts with **zero artificially entered triage decisions**.

## Research next step
Use the acquisition worklist to identify eligible source articles, confirm publication identities and extract exact assay endpoints. Approved measurements can subsequently enter protocol-governed cross-study harmonization. No meta-analytic effect or individual CFTR treatment-response probability is generated by this phase.
